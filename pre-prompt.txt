این پروژه با نام "سیمرغ افزار" یک پروژه ERP برای یک کارخانه تولیدی در ایران تحت مالکیت شرکت تأمین نهاده سیمرغ است

همه مدل های صالی به صورت مرتب و یک دست در اپلیکیشن core موجودند

موارد زیر در توسعه اهمیت زیادی دارند:
1- همه کدها باید لاگ های دقیق و حرفه ای در فولدر logs داشته باشند
2- همه استایل ها باید از استایل base.html اصلی در فولدر templates اصلی پروژه تبعیت کنند =
3- استایل ها باید ساده، و با رابط کاربری ای ریسپانسیو مناسب گوشی و تبلت باشند
4- همه فرم ها باید با django forms طراحی شوند
5- همه جداول باید با جدول های django-datatables2 رندر شوند
6- نیازی به نوشتن README نیست

لطفا برای هر تابع view لاگ بزار.
در ابتدای فایل هایی که نیاز به لاگ دارند، اینگونه لاگ ها را ایمپورت کن:
import logging
from core.logging_levels import *

bug_logger = logging.getLogger("bugs")
audit_logger = logging.getLogger("audit")

توضیحات راجب لول های لاگ:
لول ها:
bug_logger.debug("...")
 .برای چیز های دیباگ طور. مثلا فلان خرید لود شد.  اینا تو فایل نمیان و فقط تو کنسول یا circular_buffer میان پس عیب نداره اگه اطلاعات توش باشه.

bug_logger.info("..")
  این توی فایل میره، برای همین چیزای دیباگ رو اینجا ننویسیم، و اطلاعات حساس هم قرار ندیم (شماره و ... نباید توش باشه). اجباری نیست، فقط اگه به نظرتون یکم مهمه بزارید. مثلا خرید جدید اضافه شد

bug_logger.warning("...") 
این برای خطاهاست. ولی خطاهایی که باعث خراب شدن کل پیج نمیشن. مثلا اگر که موقع لود کل صفحه خرید، یکی از خرید ها لود نشد، از warning استفاده میکنیم. اینجا برای دیباگ میشه اطلاعاتی قرار داد.

bug_logger.error("...")
این برای خطاهای بزرگ تر و جامع تره. اکثرا توی try و except که برای کل تابع مینویسید، از این استفاده کنید. یعنی خطاهایی که باعث میشه کل یا اکثرا تابع کار نکنن، یا وارد except ای بشن که منتهی به return بشه.


audit_logger.info(...)
اول تابع مینویسیم که چیکار میکنه. خودش اتومات یوزر و ایپی ثبت میکنه شما نمیخواد بزارید. مثلا "دسترسی به خرید ... توسط کاربر.". اینجا هم خیلی اطلاعات نمینویسیم، ولی از bug_logger.info یکم شل تره. باز هم اطلاعات حساس مثل قیمت و ... توش نباید بیاد. شماره های درون سازمانی (مثل شماره خرید و ...) ولی اوکیه.

audit_logger.activity(...)
برای جاهایی که کمی احتمال هک یا دور زدن سیستم هست، ولی هنوز قطعی نشده و ممکنه از اشتباه غیرعمد کاربر باشه یا مرورگر. برای مثال فرستادن فایل با حجم بیشتر از حد، یا مثلا درخواست به خرید یک نفر دیگه.

audit_logger.alert(...)
این برای موقعی که خیلی مشکوکه و تقریبا غیرممکنه یکی از غیرعمد کرده باشه و قطعا برای تخریب بوده. برای مثال تلاش برای دسترسی به پنل ادمین، یا فرستادن فایل خیلییی سریع، یا فرمت غیر مجاز، یا فرستادن post وقتی تابع getعه، یا وقتی تابع یک سری آیدی میخواد ولی آیدی ای داده نشده.
